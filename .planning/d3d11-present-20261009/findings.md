# Findings

Frozen offscreen probe has 512 literal RGBA pixels, typed11 FL10_0 negotiation, KMT selected adapter identity, exact system/private module paths and held external restoration. Its marker honestly declares presents=0. This follow-on will use separate files, retaining the existing probe/reader byte-for-byte.

The existing D10 path renders into a 16x16 RGBA swapchain backbuffer, stages clear/draw pixels before each Present(1,0), and records GetDeviceRemovedReason after each call. Present success alone is distinct from desktop/DWM pixels. Use DXGI factory obtained from the actual created adapter and retain swapchain/window through external restoration, then release all device-owning objects before closed negotiation. New Present files will duplicate the explicit frozen entry/identity mechanics to avoid modifying the offscreen files.

Microsoft local DXGI presentation-path docs confirm windowed DWM-on Present follows shared-resource Blt and needs an independent DWM proof. The official public Present documentation confirms positive DXGI_STATUS_OCCLUDED is possible, so both exact S_OK results are required. DISCARD does not preserve the backbuffer: each frame now clears the full buffer and explicitly rebinds the RTV before draw. New probe captures window PID/thread/session and descriptor, accepts no Session 0 or foreign HWND, rechecks exact private modules after both Presents, verifies user32.dll against System32, destroys its owned window/class after external release, and only then saves closed typed negotiation.

Independent source review found no core regression; the original held wait does not pump UI messages and the documentation now states this limit. Timeout cleanup fails the attempt and external restoration remains required. A final guard is under consideration to prevent the default DXGI Alt+Enter association from changing the explicit windowed scope between the initial descriptor and Present.

Peer confirmed a real source-scope bug in attempt01: default DXGI Alt+Enter can be dispatched by readyWindow after the initial descriptor, leaving a stale windowed claim. The new source disables Alt+Enter/window-mode changes on its owned factory/window, then requires successful GetFullscreenState == FALSE immediately before and after both Presents. The independent manifest/reader now requires those same-attempt observations and exact association result/flags. Attempt01 remains preserved and superseded for source admission; fresh attempt02 is necessary because C++/reader/control inputs changed.
