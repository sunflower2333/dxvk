# Backend predication and private transfers

This change repairs internal nonshared resource rotation and Present's resolve/readback copies. Both now record a private deferred command list and execute it with application state restoration. The synchronized readback Map, allocation upload, callback, resource pins, rotation preflight and post-copy identity swaps retain their existing ownership rules. A command list only enters the immediate stream while its caller's resource reservations remain live. The list retains its textures after submission. Failed allocation upload does not publish a Present callback; a retry rereads the current image. This is an internal correctness fix, with all hardware admission gates unchanged.

The append-only typed DXGI Blt fixture runs these production paths under an issued non-hint FALSE WARP occlusion predicate. Each D10, D10.1 and D11 table records three rotation images, a Present backing, a four-sample resolve backing, an ordinary application Copy/Update sentinel, an unchanged backing after LockCb failure, and a successful retry backing. It also verifies predicate, shader, target, topology, raster, viewport and scissor retention and nested Present/rotation rejection during upload. Its independent reader requires 24 snapshots, 840 complete RGBA words and 48 closed originals, including backing guards. Legacy 30/1536 and identity 120/15624 oracles remain unchanged. WARP fixture execution is required in native CI; Linux cross compilation is not a GPU execution result.

## Why the backend stub is still a separate blocker

The local Microsoft `PFND3D10DDI_SETPREDICATION` contract (`reference/codes/windows-driver-docs-ddi/wdk-ddi-src/content/d3d10umddi/nc-d3d10umddi-pfnd3d10ddi_setpredication.md`) states that an equal query result and predicate value suppress render/resource commands, except that predicate-hint queries may choose not to suppress. The public D3D11 implementation in `src/d3d11/d3d11_context.cpp` still only updates `m_state.pr` and logs that SetPredication is a stub. The UMD CPU suppression path in `src/umd/umd_ddi.cpp` has separate command classification and non-hint waiting; these internal private command lists do not remove the public backend gap.

`src/d3d11/d3d11_query.cpp` currently obtains a Boolean by CPU reduction of occlusion/stream-output query data. `src/dxvk/dxvk_gpu_query.cpp` accumulates multiple segmented 64-bit Vulkan query slots using `vkGetQueryPoolResults`. There is no GPU 32-bit per-generation Boolean predicate buffer/reduction, and `src/dxvk/dxvk_device_info.{h,cpp}` has no conditional-rendering feature/extension query or enable chain. `src/vulkan/vulkan_loader.h` only declares the conditional command entry points. These are current source observations; target Vulkan capability was not queried by this local-only task.

[Vulkan conditional rendering](https://docs.vulkan.org/refpages/latest/refpages/source/VK_EXT_conditional_rendering.html) covers draws, dispatches and attachment clears, and explicitly excludes copies and blits. [vkCmdCopyBuffer](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdCopyBuffer.html) is unaffected. Therefore wrapping graphics/compute calls in conditional rendering would leave D3D resource-command semantics incomplete. Secondary-command-buffer inheritance also requires its feature and correctly scoped state. [The inverted flag](https://docs.vulkan.org/refpages/latest/refpages/source/VkConditionalRenderingFlagBitsEXT.html) executes when the predicate is zero; for D3D's equal-means-suppress rule, PredicateValue FALSE maps to normal nonzero execution, and TRUE maps to inverted execution. Hints may skip suppression but cannot invert that rule.

A complete backend implementation needs capability plumbing; query-generation-safe GPU Boolean reduction; correct scopes and restoration for immediate/deferred graphics and compute; inversion and hint handling; and a transfer-command strategy covering Copy, Update and Resolve where Vulkan conditional rendering does not. CPU waiting in an unsubmitted command-stream task can deadlock on the query being awaited, so a superficial GetData wait in SetPredication is not a safe substitute.

A real GPU test must issue both FALSE and TRUE queries, test both PredicateValue settings and the hint case, preserve predication across command-list restore/reset, verify graphics, compute/UAV and every public transfer class using exact raw buffers/images, and include query reissue/lifetime controls. Until those execute on the actual backend and target, no feature/admission bit should be broadened.
