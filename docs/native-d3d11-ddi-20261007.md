# Typed native D3D10.1 and D3D11 device DDIs

The native device factory now selects `D3D10DDI_DEVICEFUNCS`,
`D3D10_1DDI_DEVICEFUNCS`, or `D3D11DDI_DEVICEFUNCS` using the exact SDK interface
and build. Each table is populated through its own function pointer types.
The implementation shares the existing independently owned Device/Resource
registry and caller-thread runtime service. It keeps the original D3D10 or
D3D11 core callback table pointer and reads mutable callback slots when used.
DXGI table selection uses the SDK revision predicate rather than assuming a
DXGI layout from the D3D interface alone.

The production backend remains the private exact-LUID DXVK D3D11 core. The
new source-linked test helpers are not DriverStore adapter registration or
public `D3D11CreateDevice` replacements.

## Implemented slice

- D3D10.1 independent blend state and cube-array SRV descriptors, with typed
  relocation and same-format resource conversion through existing copy DDIs.
- D3D11 field-wise resource creation for ordinary buffers and 1D/2D/3D/cube
  textures; explicit native bind, CPU access, misc flag and structured stride
  translation. Existing plain shared/present resources retain KMD ownership.
- Typed/raw/structured buffer SRVs, cube-array/3D SRVs, readonly DSVs, buffer
  and texture UAVs, integer/float clears, append/counter initialization and
  `CopyStructureCount`.
- SM5.0 compute tokens wrapped unchanged into an upstream-parser-validated,
  hashed SHEX container; compute shaders, resources, samplers, constant
  buffers, direct and indirect dispatch. Indirect draw arguments use real
  backend draw calls and the existing graphics readiness checks.
- Typed OM RTV/DSV/UAV binding with full validation before commitment and
  omitted UAV tail clearing; minimum resource LOD for clamp-enabled textures.
  Foreign owners, invalid ranges, flags and offsets report runtime errors.

Command-list entries remain NULL because no command-list capability is
advertised. Tessellation creation, dynamic class linkage and general SM5
graphics/GS stream-output semantics are incomplete and explicitly reject
unsupported work. Conversion across different resource formats is also
incomplete. The higher-interface admission predicates from the companion
adapter change retain independent immediate/compute/tessellation/interface
gaps: this commit does not enable ordinary D3D10.1 or D3D11 runtime admission,
clear hardware/presentation acceptance gates, or claim that WARP proves the
phone GPU path.

## Verification

`tests/umd-compute-container.cpp` runs without Windows. Its 35 checks validate
exact retained tokens and hash, upstream parse, wrong stages/versions, missing
or duplicate thread groups, instruction bounds and invalid group dimensions.
It passed locally using the repository-pinned dxbc-spirv parser and hash code.

`tests/umd-d3d11-device.cpp` links the actual native DDI implementation with a
test-only WARP backend. It checks typed table bounds, child storage canaries,
failed creation rollback/retry, dynamic D3D10.1/11 caller-thread callbacks,
independent blend descriptors, clamp texture LOD, SM5 compute results,
indirect dispatch, raw/float UAV clear readback, append/counter reset and
preservation, foreign-device transaction rejection, explicit unsupported
tessellation/class linkage, and feature-level rejection. The real SDK/WDK
26100 headers type-check this fixture and production DDI on local x64 and
x86 Windows clang targets with strict warnings. Native ARM64 MSVC compilation and WARP execution are
pending the root-coordinated target run; no execution receipt is claimed here.

The constexpr descriptor contract compiles against the SDK and specifically
checks the native UAV bind bit (0x100) becoming the public API bit (0x80), CPU
access translation, structured stride and rejected raw/structured combinations.

## Native fixture inputs

Meson targets are `src/umd/dxvk-umd-d3d11-device-test.exe` and
`src/umd/dxvk-umd-compute-container-test.exe`. Build in a selected native
MSVC environment with the official SDK/WDK containing `d3d10umddi.h`,
`d3dkmddi.h`, public D3D11/DXGI headers, UCRT/STL and WRL. Include the pinned
`subprojects/dxbc-spirv` root. All new D3D11 helper headers are included from
`src/umd/umd_ddi.cpp`; no new production CPP owner is required. The companion
adapter commit supplies `umd_interface.h` and the per-interface contract.

For an explicit source-linked native build, compile these shader objects:

```text
src/umd/umd_shader.cpp
subprojects/dxbc-spirv/dxbc/dxbc_container.cpp
subprojects/dxbc-spirv/dxbc/dxbc_parser.cpp
subprojects/dxbc-spirv/dxbc/dxbc_signature.cpp
subprojects/dxbc-spirv/dxbc/dxbc_types.cpp
subprojects/dxbc-spirv/ir/ir.cpp
subprojects/dxbc-spirv/util/util_swizzle.cpp
subprojects/dxbc-spirv/util/util_log.cpp
subprojects/dxbc-spirv/util/util_md5.cpp
```

Compile these actual DDI objects:

```text
src/umd/umd_ddi.cpp
src/umd/umd_runtime_query.cpp
src/umd/umd_allocation.cpp
src/umd/umd_runtime_gpu.cpp
```

Link `tests/umd-d3d11-device.cpp` with both object lists and `d3d11.lib` and
`d3dcompiler.lib`. Link `tests/umd-compute-container.cpp` with just the shader
object list. No `umd_backend.cpp`, substituted UMD DLL, public D3D11 frontend
or new D3D9 source is involved. Use `/std:c++17 /EHsc /O1 /MD /bigobj
/DNOMINMAX`, and `/W4 /WX /external:anglebrackets /external:W0` for the native
fixture check. Compile in a fresh architecture-specific artifacts directory,
inspect PE machine type, and bound fixture execution to 60 seconds. The root
build script owns consolidated CI/run integration.
