# Public DXVK predication fallback

This is a design for the remaining implementation, plus one implemented query-generation prerequisite. `D3D11DeviceContext::SetPredication` remains a stub. No draw, dispatch, copy, update or resolve is newly conditionally executed by this change, and all ordinary-runtime/hardware admission gates remain unchanged.

## Current source constraints

`D3D11CommandList::EmitToCsThread` calls `DoDeferredEnd` for every recorded query before dispatching the first CS chunk. A non-hint predicate wait inserted between chunks can therefore wait for a future End/reissue whose chunk has not been submitted. Query `m_resetCtr` historically counted pending resets without identifying an issue generation. `D3D11ImmediateContext::GetData` inspected the non-atomic API query state before taking the immediate context lock. `D3D11Query::GetData` also had no issue-generation check between obtaining virtual Vulkan query data and publishing an output.

CS chunks are not predicate operations. They contain state bindings, query Begin/End and predicatable commands, including draw batching. Skipping a chunk would skip unconditional work. `UpdateResource` can use `UpdateMappedBuffer`, whose CPU write/discard path is performed on the API thread rather than exclusively inside a CS lambda. Conditional suppression must precede those destination mutations; filtering the later Vulkan command is insufficient.

## Implemented prerequisite

`D3D11QuerySequence` retains the existing initial/begun/ended and all-End-up-front pending behavior, adds an atomic issue generation, and makes API issue state race-free. It marks readiness false before publishing a new End generation. Public query reads capture a stable state and recheck the exact generation before publishing event/query data. A completed reissue that brings the pending count back to zero cannot validate an old ready ticket. Immediate `GetData` now takes the same context lock as Begin/End before reading query state; normal D3D threading rules still apply when multithread protection is disabled.

This helper does not provide historical GPU results or enable intermediate deferred-list waits. Its final generation check is not an atomic check-and-output operation for an unlocked internal caller: public correctness relies on the context lock or the application's required serialization. Existing `Com<D3D11Query>` CS captures and command-list query pins retain ownership; no lifetime path is replaced. Boolean occlusion/SO-overflow decoding, GPU query aggregation, public invalid/pending statuses and command emission remain otherwise unchanged, including the inherited event-query pending output of `BOOL(FALSE)` with `S_FALSE`. Host tests execute the actual production sequence helper, including implicit End, explicit/repeated Begin, repeated deferred Ends, zero-count reissue, stale-output canaries for both Boolean values and serialized API issue/concurrent CS completion/readers. They are not GPU predication tests.

## Complete fallback architecture still required

1. Record ordered operation entries separate from CS chunks: unconditional state/query work, individually predicatable draw/dispatch/clear/transfer actions, predicate state transitions and exact query issue notices. Preserve command/resource sequence-number tracking and COM/backend resource pins. Batch only actions with the same predicate ticket; never batch across a query issue or predicate transition.
2. For immediate calls, evaluate a non-hint predicate on the API submission thread before every predicatable destination mutation. Submit the prefix containing its relevant query End, flush the current CS chunk, synchronize that prefix's CS sequence and submission, then poll the exact issued generation's GPU result. Never wait within the CS lambda or while holding a lock needed by submission/completion callbacks. A lost device cancels the wait; a timeout cannot silently turn a non-hint predicate into unconditional execution.
3. For deferred replay, advance ordered query issue notices only when their operation is reached. Replace all-End-up-front accounting for internal predicate reads with per-generation results/tickets. A query End in the prefix must be able to resolve without depending on later reissues. Retain each generation's virtual Vulkan query data until all actions using that generation have evaluated; a later Begin must not clear the data still owed to an earlier predicate action.
4. Capture source bytes during deferred Update calls as the API requires, but defer destination writes, discards/renames and GPU resource mutations until the guarded operation is replayed. Preserve original relative source-box behavior, transfer block geometry, resource aliases, barriers and staging/resource sequence tracking. Public Map/Unmap remains unconditional; private ownership/Present command lists begin with no predicate.
5. Reset predicate execution state at command-list entry and cleanup. Restore the immediate/deferred API predicate when restore is TRUE, and restore default predicate state when FALSE. Nested deferred ExecuteCommandList must preserve operation ordering and relocate resource/query metadata together. GetPredication must return the exact stored value even when the predicate pointer is null.
6. Suppress when a resolved Boolean equals PredicateValue: FALSE/FALSE and TRUE/TRUE suppress, the other two execute. A hint query may choose unconditional execution and must not require forbidden public query polling. GPU conditional rendering can optimize graphics/compute later, but it does not replace transfer semantics.

Local Microsoft `PFND3D10DDI_SETPREDICATION`, `QUERYBEGIN`, `QUERYEND` and `QUERYGETDATA` docs are in `reference/codes/windows-driver-docs-ddi/wdk-ddi-src/content/d3d10umddi/`. They define equal-means-suppress, allowed hint behavior, issued/signaled states and the predicate-hint polling restriction. QueryEnd is prohibited on a predicate currently bound to the pipeline, so the reissue controls must first unbind that predicate. Source method locations are pinned in the local frozen packet. Target Vulkan capability remains unqueried by this source-only task.

## Native acceptance matrix

The actual DXVK backend must execute exact raw-buffer/image controls for every draw variant (including Auto/indirect), dispatch/direct-indirect compute/UAV, render/depth/UAV clears, mip generation, CopyResource/CopySubresourceRegion/CopyStructureCount, UpdateSubresource/UpdateSubresource1 including direct mapped-buffer fast paths, ResolveSubresource and any admitted tiled transfers. Include all four Boolean/value combinations, hint and non-hint predicates, null predicate, issued-but-incomplete query, same-query reissue after unbinding, same-list repeated replay, query/resource release after recording, nested deferred lists and restore TRUE/FALSE. State changes and legal unbound query Begin/End must execute while rendering is suppressed. Exact output and state oracles must fail against the existing stub. All classes remain unproven until that matrix runs on the real backend and target.
