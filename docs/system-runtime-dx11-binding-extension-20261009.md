# Same-owner SYSTEM D11 FL10_0 validation binding

`test-system-d3d10-binding.ps1 -Api 11` selects zero-based native tuple index2.
The local Microsoft `enabling-support-for-the-direct3d-version-11-ddi.md`
requires D11's third UserModeDriverName entry, including shared DLLs; the
retained official d3dkmthk.h enum defines KMTUMDVERSION_DX11 as2. The matching
initialization document requires OpenAdapter10_2, its modern adapter table and
version/caps discovery, and explicitly distinguishes D11 DDI from FL11 hardware.

This is an extension of frozen ac77's single owner. The default stays Api10,
with its original second-slot entry and five typed entry controls. D9/9Ex
retain first-slot selection, exact ten operands, production child-core layout
and closed739 hold schema. D11 uses the same global adapter lease, outstanding
rescue exclusion, protected backup/config, restoration mutex and service rescue
task. Exact prewrite raw readback still precedes durable intent and RegSet.
Schema2 intent now admits the selected native slot0,1 or2. A foreign owner/key/
slot is rejected; no intent cancels without replaying a stale backup. Restoration
still replays and reads all six original existence/kind/byte values. No second
registry owner, workflow, signed KMD/image, capability or production mask changes
are supplied. Frozen648/ac77 source and proof packets remain untouched.

Peer `port_dx11` owns the dedicated modern forwarder and SYSTEM probe in
`reference/codes/dxvk-umd-d3d11-system-validation-20261009`, frozen as
0151b8bff2331b32bb2551e95f43e695dd0c5f44 plus the DEF-only
82963f0b9456467e725f5c9832c03c53d9693bfe correction. Its modern entry
calls only `VioGpuDxvkOpenAdapter11Fl10_0ForValidation` from dedicated a103,
integrated as6b40a0f. ROOT must admit matching actual source/core/native build
inputs before binding; a production or generic private modern entry does not
stand in for that dedicated contract. The separate `--entry-negative <front>`
mode must pass all nine actual typed controls with no core load before worker
readiness. D11 normal mode has nine operands after EXE:

```text
LUID front core private-loader ICD-DLL owned-ICD-JSON rawdir Local-event 60000
```

The actual DLL is resolved and pinned through the owned ICD JSON. The worker
sets both Vulkan manifest environment variables to that exact JSON. The
private loader remains the reviewed actual `winevulkan.dll` core sibling.
The actual pinned probe's bounded PE machine header selects D11's same-directory
`viogpudxvk.dll` for ARM64 or `viogpudxvk_x64.dll` for x64. This layout boundary
does not certify a complete PE or native build. Genuine KMT version2 must name
the candidate before the SYSTEM D3D11 factory can succeed; no fallback entry,
WARP, capability inflation or manually loaded candidate is accepted.

The D11 producer writes `<rawdir>.held.json` with share0, flushes and closes it
before its bounded wait. The owner reuses retrying ReadClosedText and checks
the complete schema1/api11 field set, process ID, timeout, output path, event,
boolean factory/pixel flags and signed HRESULT values. A failed factory or
readback still publishes a held failure so the original tuple is restored
before child release/cleanup. Positive release requires the existing protected
full raw-restoration proof and fresh original KMT-name query. Final success
requires the same retained runner PID, zero actual exit, closed/drained pipes,
no stderr/timeout/live child and both exact D11 held/success markers. The closed
event checkpoint and stdout do not themselves prove registry restoration or
literal pixels.
