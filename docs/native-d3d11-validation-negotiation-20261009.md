# Dedicated ordinary SYSTEM D3D11 validation negotiation

`VioGpuDxvkOpenAdapter11Fl10_0ForValidation` uses the exact modern adapter ABI and publishes one DDI version, `D3D11_0_DDI_SUPPORTED`. Its pipeline capability is only `D3D11DDI_3DPIPELINELEVEL_10_0` (Caps=1); threading, command-list, and optional shader capabilities remain zero. Device sizing and creation accept only the D3D11.0 interface at the existing supported build, with logical FL10.0 and either no flags or `SINGLETHREADED`. Higher logical profiles, D3D10.x interfaces, unknown flags, and disable-extra-thread requests are rejected.

The tag belongs to one retained adapter token and ends at CloseAdapter. This entry uses the strict callback path: required kernel callbacks, DXGI PresentCb and the selected DXGI output table must be present. Kernel callback inputs are copied before reentrant identity queries; core and DXGI callback table addresses remain the runtime-owned live pointers. Both typed output tables publish only after actual backend creation and a second matching identity/generation check. No table casts, substitute factory, or synthetic device success are added.

The existing production exports and immutable missing-requirement masks are unchanged. The generic modern ForTest entry still reports three versions and zero production pipeline caps. The new entry resolves the test-only negotiation cycle: ordinary SYSTEM D3D11 could not reach CreateDevice through a forwarding frontend while the ordinary-runtime proof itself was required by production admission. A separate validation frontend forwards only this dedicated export; the existing binding owner controls temporary installation and restoration. This source does not write registration.

The validation run must bind the accepted current core/source/CI and genuine process-local Mesa loader/ICD originals, an actual selected nonzero LUID and matching 160-byte private reply, real KMT RenderSupported/nonsoftware status, and supported runtime callbacks. The embedded renderer privately requires FL11.0 even when its logical profile is FL10.0; the real selected Turnip backend must satisfy that implementation requirement. A current-core typed11 baseline hardware draw/readback/transfer/teardown control is a prerequisite. Actual ordinary SYSTEM D3D11 factory, pixels, Present, callback lifetime, and cleanup evidence are still required. This entry does not admit a complete production feature level.

The existing typed adapter fixture covers exact supported-version sizing, one-entry guarded output, pipeline/optional caps, captured output ownership, strict missing callbacks, all rejected profiles, and both DXGI revisions. Its additional creation cases cover backend failure, allocation exception, positive non-S_OK status, reentrant close before/after construction, reset, query failure/exception, live callback replacement, and stale-token replacement. The fixture uses an explicitly linked mock backend and proves adapter behavior, not native rendering. Portable controls replay exact source policy bodies; optimized x64/x86 COFF compilation uses original Microsoft SDK/WDK headers. Native ordinary behavior remains pending.

Official local sources are the WDK26100 `d3d10umddi.h` and the Microsoft DDI documents for GetSupportedVersions, GetCaps, D3D11DDI_3DPIPELINESUPPORT_CAPS, and D3D11DDI_3DPIPELINELEVEL. The runtime selects DXGI1.0 or1.1 independently through the original `IS_DXGI1_1_BASE_FUNCTIONS` version macro; this export does not rewrite that revision.
