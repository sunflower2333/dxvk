# Typed sRGB resolve and original default views

This follows frozen406e9b5. The production DXGI Blt entry still requires BIND_PRESENT before building a plan. Its PRESENT cache is already typeless. Ordinary non-PRESENT sources remain rejected without changing the destination.

The reusable Blt helper also accepts plans for a fully typed sRGB image. Microsoft’s typed ResolveSubresource rule forbids resolving that source directly into UNORM under a UNORM format. The helper now allocates a same-family UNORM multisample image with the source count/quality and selected mip size, copies the physical samples into it, then resolves to the single-sample UNORM scratch. All images and pipeline state are allocated before command recording, and the existing live checks and command-list state restoration remain. No CPU remapping, intrinsic substitute or color decode is involved.

For the six supported fully typed PRESENT families, UNKNOWN SRV/RTV descriptors now retain the original resource format rather than the private typeless cache format. This also preserves ordinary fully typed default views. Explicit family UINT/SNORM/SINT casts remain legal only for PRESENT resources. UNKNOWN emission by the system DDI runtime has not been observed here; this is default-view compatibility preservation.

The existing bounded WARP fixtures now add a genuine fully typed non-PRESENT BGRA sRGB MSAA helper source with disjoint black/white sample masks: the encoded resolve must produce128, while decoded resolve would produce188. A separate production Blt call is required to reject that source and leave its initial destination untouched. Default ordinary and PRESENT SRV/RTV descriptors and actual RGBA UINT/default backend formats are checked. Two added RGBA primary snapshots preserve the allocation identity and physical bytes. D10.1, D11 FL10.0 and D11 FL10.1 yield57 Blt images/1260 pixels and18 primary images/576 pixels; the independent reader requires171 original files and1836 literal pixels. Original SDR fixture counts and readers remain unchanged.

Local checks are strict genuine26100 SDK/WDK x86/x64 O2 compilation of production DDI and both new/old fixtures,6775 primary-policy ASan/UBSan checks,3444 cast/default-policy ASan/UBSan checks against the original SDK enum, and13 invented-input independent-reader rejection controls. The invented fixtures prove reader rejection behavior only. Native WARP execution, native PowerShell parsing, real scanout/Present and system factory acceptance are still pending. No hardware, ordinary-runtime, HDR/stereo or default-driver gates changed.

Official local sources are the Microsoft DDI ResourceResolveSubresource and ResourceCopyRegion documentation, fully-typed-back-buffers-casting.md, and the original backend RTV/SRV NormalizeDesc default-format behavior.
